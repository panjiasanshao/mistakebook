# 通用项目工作约定

面向非技术用户，用功能、动作和可见结果沟通。工具检查使用 ai-coding-env，项目启动与恢复使用 ai-coding-project。技术选择采用已准备环境的默认能力。先读取项目需求、原型和现有代码；未确认产品目标时不生成业务页面。

每轮功能迭代，包括本机、云端、安卓和各项 AI 功能，都先明确本轮目标，引导用户与 Gemini 新建或更新 PRD.md，在 Canvas 新建或更新 HTML 并试用确认，再分步实现与实际测试，最后给用户验收入口与动作并记录结果。不索要技术规格书。文件已存在仍需核对本轮变化；本轮材料已确认时直接使用，不重复审批。实现偏差直接修复与复测；用户改变功能或规则时先更新需求和设计。保留原版材料与已有进度。

连续完成本轮已确认的技术工作，分步实现不等于逐项等待用户批准。按变更风险执行必要检查，不重复无变化的完整构建；交付时集中给用户入口与验收动作。案例 Skill 约定集中验收节奏时按案例执行。保持用户已有设计。业务规则、云端环境、账号策略、AI 任务及模型来自本项目需求或显式项目配置，不从工具箱名称推断。个人密码、管理令牌与服务端密钥不进入聊天、代码或产物；显式允许公开的演示配置按所选案例规则处理。

## 容器工具

当前选择 Docker Desktop；读取根目录 .ai-coding/project.json 的 containerRuntime 与工具准备记录，使用 docker compose/exec。恢复时沿用已有选择，不安装另一套，不覆盖用户资料。Podman 的 rootless/pasta、代理与离线镜像证据按 ai-coding-env 的 windows-podman-setup.md 执行；构建、网页、云端与真机分别记录。

## 初始化与作品信息

初始化不要求本人先提供项目名称或用途；缺少时使用中性占位信息，空白工作空间可独立验收。完成需求与 Canvas 原型并确认后，调用 ai-coding-project 按实际材料补全 name、purpose、nameSource、identityStatus 与展示信息，记录来源；保留 slug、appId、目录、端口、Compose 标识和容器选择。不为补名称重建工程，不要求学员另填技术信息；不预设案例业务。
